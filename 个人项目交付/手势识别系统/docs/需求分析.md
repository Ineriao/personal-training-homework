# 静态手势识别系统需求分析

## 1. 需求概述

用户选择一张包含手部的图片，系统加载训练好的检测模型，识别图片中的手势类别，并在界面中显示标注后的图片、目标数量、主要手势和每个目标的置信度。

## 2. 用户角色

| 角色 | 说明 |
| --- | --- |
| 使用者 | 选择图片、启动识别、查看结果和清空界面 |
| 维护者 | 替换模型、调整阈值、检查运行环境和处理错误 |

## 3. 功能需求

| 编号 | 需求 |
| --- | --- |
| FR-01 | 系统应支持打开 JPG、JPEG、PNG 和 BMP 图片。 |
| FR-02 | 系统应检查图片是否能够正常读取，失败时给出提示。 |
| FR-03 | 系统应加载 YOLO 手势检测模型并执行推理。 |
| FR-04 | 系统应显示模型绘制的检测框、类别和置信度。 |
| FR-05 | 系统应显示目标数量和主要手势类别。 |
| FR-06 | 系统应支持调整识别置信度参数。 |
| FR-07 | 系统应支持清空当前图片和识别结果。 |
| FR-08 | 模型不存在或推理失败时，系统应显示明确错误信息。 |
| FR-09 | 推理过程不应阻塞窗口操作。 |

## 4. 非功能需求

- **易用性**：打开图片和开始识别两个主要操作应能直接找到。
- **可维护性**：模型路径、界面显示和推理逻辑分开组织。
- **可移植性**：交付包不能依赖开发机的绝对路径。
- **稳定性**：窗口关闭时释放工作线程，图片读取失败时不进入推理。
- **可扩展性**：类别名称和模型文件可以替换，后续可扩展摄像头或视频输入。

## 5. 用例

### 用例 UC-01：识别手势图片

1. 使用者启动程序。
2. 使用者点击“打开图片”，选择合法图片。
3. 系统显示原图。
4. 使用者点击“开始识别”。
5. 系统在工作线程中加载模型并完成推理。
6. 系统显示标注结果、目标数量、主要类别和置信度。

异常情况：没有选择图片时点击识别，系统提示先打开图片；模型文件不存在时，系统提示模型路径错误。

### 用例 UC-02：清空当前结果

1. 使用者点击“清空”。
2. 系统移除预览图片和表格内容。
3. 系统将目标数量恢复为 0，将主要手势恢复为默认状态。

### 用例 UC-03：处理不可读图片

1. 使用者选择损坏或格式不支持的图片。
2. 系统检查 `QPixmap` 是否为空。
3. 系统弹出读取失败提示，不开始模型推理。

## 6. 术语表

| 术语 | 含义 |
| --- | --- |
| YOLO | 用于目标检测的单阶段深度学习模型系列。 |
| 目标检测 | 同时确定目标类别和目标位置的任务。 |
| 边界框 | 包围目标的矩形框，使用中心点、宽度和高度表示。 |
| 置信度 | 模型对检测结果可信程度的数值。 |
| mAP50 | IoU 阈值为 0.5 时的平均精度指标。 |
| mAP50-95 | IoU 从 0.5 到 0.95 多个阈值下的平均精度。 |
| 工作线程 | 在界面主线程之外执行推理任务的线程。 |
